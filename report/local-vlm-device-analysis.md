# 本地 VLM 部署可行性分析 - RTX 4060 Laptop 8GB

> 日期：2026-03-03
> 设备：Intel i9-14900HX / RTX 4060 Laptop 8GB VRAM / 32GB RAM
> 目标：评估本地部署 VLM 实现 Phase 1（图片→参数）和 Phase 2（轮廓提取）的可行性

---

## 1. 设备约束分析

| 硬件 | 规格 | 对 VLM 的意义 |
|------|------|--------------|
| GPU | RTX 4060 Laptop, **8GB VRAM**, CUDA 8.9 | 可运行 4B 模型(舒适) / 7-8B 模型(Q4 勉强) |
| CPU | i9-14900HX 24C/32T | CV 计算充裕，可辅助 CPU offload |
| RAM | 32GB DDR5 | 可承担 CPU offload 溢出 |

**实际可用 VRAM：~6.5-7GB**（OS/显示占用约 0.5-1GB）

VLM 的 VRAM 构成：
- 模型权重（主要占用）
- 视觉编码器（SigLIP ~0.8-1.5GB 额外）
- KV Cache（随上下文长度增长，2K≈0.2GB，8K≈1-2GB）

---

## 2. Phase 1 与 Phase 2 的工具选择

### 关键结论：两个阶段应使用不同工具

| 阶段 | 任务 | 最佳工具 | 原因 |
|------|------|---------|------|
| **Phase 1** | 形状分类、比例估计、特征识别 | VLM | 需要语义理解（"圆顶""锥形"等） |
| **Phase 2** | 2D 轮廓提取 → spline 控制点 | **CV (OpenCV + SciPy)** | 精确像素级操作，VLM 不擅长 |

Phase 2 的轮廓提取流程（纯 CPU，无需 GPU）：
```
图片 → Canny 边缘检测 → findContours → 对称轴检测 → 取半轮廓
    → scipy.interpolate.splprep() 拟合 B 样条
    → 输出 5-8 个控制点 → CadQuery spline().revolve()
```

**因此，本地 VLM 的 VRAM 需求仅针对 Phase 1。**

## 4. 推荐方案

### 首选：Qwen3-VL-4B

| 项目 | 值 |
|------|---|
| VRAM 占用 | ~3.5-4.5GB (Q4)，留足余量 |
| 推理速度 | ~40-50 tok/s |
| 几何理解 | 原生 bounding box + 点标注 JSON |
| Thinking 变体 | 可选，思维链提升空间推理精度 |
| 部署方式 | Ollama 一行命令 |

```bash
# 安装 & 运行
ollama pull qwen3-vl:4b
ollama run qwen3-vl:4b
```

### 质量升级：Qwen2.5-VL-7B (Q4)

当对精度要求更高时切换，需控制上下文长度（2-4K tokens）和图片分辨率（≤768px）：

```bash
ollama pull qwen2.5-vl:7b-q4_K_M
```

### 原型验证：Moondream2

极轻量（1.86B），用于快速验证 pipeline 流程：

```bash
ollama pull moondream
```

## 6. 推荐架构：混合模式

```
用户上传图片
       ↓
┌──────────────────────────────────┐
│  Phase 2: CV 轮廓提取 (本地 CPU)  │  ← OpenCV + SciPy, 毫秒级
│  输出: spline 控制点              │
└────────────────┬─────────────────┘
                 │
┌────────────────▼─────────────────┐
│  Phase 1: 语义参数提取            │
│                                  │
│  模式 A: 本地 VLM (Qwen3-VL-4B)  │  ← 离线/免费
│  模式 B: 云端 API (可选)          │  ← 更准确
│  用户在设置里切换                  │
└────────────────┬─────────────────┘
                 │
                 ↓
       填入参数表 → 现有 CadQuery 生成器
```

**优势：**
- Phase 2 完全不需要 GPU（OpenCV 纯 CPU）
- Phase 1 提供本地/云端双后端
- 开发时先用云端 API 验证效果，再做本地 VLM 适配
- 本地 VLM 作为离线备用方案，零成本

---

## 7. 部署注意事项

| 事项 | 建议 |
|------|------|
| 量化精度损失 | Q4 相比 FP16 约 2-5% 基准下降，需测试几何场景 |
| 图片分辨率 | 限制 ≤768×768px，减少视觉编码器内存开销 |
| 上下文长度 | 限制 2-4K tokens，避免 KV Cache 膨胀 |
| Ollama 配置 | 设置 `OLLAMA_MAX_LOADED_MODELS=1` 避免多模型同时加载 |
| 首次加载 | 模型冷启动约 5-10s，建议保持常驻 |
