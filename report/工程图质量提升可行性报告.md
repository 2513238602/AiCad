# AiCad 工程图质量提升可行性报告

> 日期：2026-03-11
> 版本：v1.0
> 范围：唇釉瓶四组件（Cap / Bottle / Wand / Wiper）SVG 工程图

## 一、现状分析

### 1.1 当前实现概述

系统在 `src/products/lip_gloss/drawings/` 下为每个组件维护独立的 SVG 工程图生成脚本（共 ~1056 行）：

| 文件 | 行数 | 生成内容 |
|------|------|----------|
| `cap_sheet.py` | 261 | 瓶盖工程图 |
| `bottle_sheet.py` | 230 | 瓶身工程图 |
| `wand_sheet.py` | 294 | 刷杆工程图 |
| `wiper_sheet.py` | 270 | 内塞工程图 |

**技术路线**：纯手绘 SVG — 根据参数值用 `rect()` / `line()` / `text()` / `circle()` 手工计算几何位置，不依赖 3D 模型投影。

**每张图纸包含**：
- A4 横向布局（297×210mm viewBox）
- 三视图横向排列：正视图 | A-A 剖视图 | 俯视图
- 简易箭头尺寸标注
- 参数文本表
- 简单标题栏（名称、规格、日期、版本）

### 1.2 已有能力（可保留）

| 能力 | 说明 |
|------|------|
| 参数化驱动 | 图纸内容完全由参数字典动态生成 |
| 自适应缩放 | `viewport()` + `fit_scale()` 防止内容越界 |
| 中文本地化 | 标题、标注、参数名均为中文 |
| 完整覆盖 | 四个组件各有独立图纸 |
| 前端集成 | SVG 通过 iframe 嵌入，支持下载 |

## 二、GB/T 国标对比与差距分析

以 GB/T 14689（图幅）、GB/T 4457.4（线型）、GB/T 4458.4（尺寸标注）、GB/T 4458.6（剖视图）、GB/T 10609.1（标题栏）等为参照基准。

### 2.1 逐项对比

| 项目 | 国标要求 | 当前状态 | 差距 |
|------|---------|---------|------|
| **剖面线** | 被剖实体填充 45° 平行细实线，间距 2-3mm | **完全缺失** | 极高 |
| **剖切符号** | 正视图标粗线段 + 箭头 + 字母"A" | **完全缺失** | 极高 |
| **尺寸界线** | 从轮廓引出细实线，超出尺寸线 2mm | **完全缺失** | 极高 |
| **不可见轮廓虚线** | 内腔等被遮挡特征用标准虚线 | **完全缺失** | 极高 |
| **尺寸箭头** | 实心填充三角形，角度 ~15°，长 ~3mm | V 形开口线条 | 高 |
| **中心线线型** | 点划线：长划-短划-长划 `dash="10,2,2,2"` | 均匀虚线 `dash="2,2"` | 高 |
| **视图投影排列** | 第一角法：俯视图在主视图正下方 | 三视图横向并排 | 高 |
| **标题栏** | 网格式，含图号/材料/签名栏/投影符号 | 简单两列文本 | 高 |
| **尺寸文字** | 纯数值 + 符号（Ø, R），竖直标注旋转 | 混用中文描述文字 | 高 |
| **公差标注** | 关键尺寸附偏差值或配合代号 | 仅瓶身有"±0.2"笼统标注 | 中 |
| **表面粗糙度** | Ra 值符号标注 | 缺失 | 中 |
| **形位公差** | 圆度/同轴度/垂直度框 | 缺失 | 中 |
| **技术要求栏** | 图纸空白区文字说明 | 缺失 | 中 |
| **图框** | 装订边 25mm，其余 10mm | 等距双线框 | 低 |
| **轮廓线宽** | d=0.5-0.7mm | sw=0.6-0.8mm | 低 |

### 2.2 核心差距总结

**当前工程图本质上是「带尺寸注释的示意图」，而非符合 GB/T 标准的工程制图。** 主要缺陷集中在：

1. **剖视图不像剖视图** — 没有剖面线、没有剖切符号
2. **尺寸标注不规范** — 箭头形状错、无尺寸界线、文字混用中文
3. **线型不正确** — 中心线用了虚线而非点划线，无不可见轮廓虚线
4. **视图排列违反投影法** — 三视图横向并排，无投影对齐关系

### 2.3 架构层面问题

- **大量重复代码**：四个文件各自独立定义相同的 `rect()` / `line()` / `text()` / `dim_h()` / `dim_v()`
- **非投影几何**：所有视图用参数手绘矩形/圆形，不反映真实零件轮廓（锥度、圆角、曲线外壁）
- **参数表替代标注**：关键尺寸以文本列表呈现而非图面标注

## 三、技术可行性评估

### 3.1 SVG 原语层改进（难度：低，收益：高）

以下改进仅需修改 SVG 绘图函数，不改变整体架构：

| 改进 | 实现方式 | 代码量 | 难度 |
|------|---------|--------|------|
| 实心三角箭头 | `<polygon>` 替代两条 `<line>` | ~10 行/函数 | 低 |
| 尺寸界线 | `dim_h()` / `dim_v()` 增加引出线参数 | ~15 行/函数 | 低 |
| 点划线中心线 | `dash="10,2,2,2"` 替代 `dash="2,2"` | 1 行/处 | 极低 |
| 剖面线 hatching | SVG `<pattern>` + `<rect fill="url(#hatch)">` | ~20 行（共享） | 低 |
| 剖切符号 | 粗线段 + 三角箭头 + 文字的组合函数 | ~25 行 | 低 |

**预估总改动**：新建共享绘图库 ~150 行 + 修改四个图纸文件各 ~30-50 行。

### 3.2 视图布局重排（难度：中，收益：高）

将三视图从横向并排改为第一角投影法布局：

```
┌─────────────────────────────────┐
│  ┌─────────┐   ┌─────────┐     │
│  │ 正视图   │   │ A-A剖视 │     │
│  │         │   │         │     │
│  └─────────┘   └─────────┘     │
│  ┌─────────┐                    │
│  │ 俯视图   │   ┌──────────┐   │
│  │         │   │ 标题栏    │   │
│  └─────────┘   └──────────┘   │
└─────────────────────────────────┘
```

**可行性**：当前已有 `viewport()` 和 `fit_scale()` 机制，重排主要是修改坐标计算逻辑。每个文件改动约 60-80 行。

### 3.3 不可见轮廓虚线（难度：中，收益：中）

在正视图中用虚线绘制内腔、螺纹等被遮挡特征。由于当前采用手绘几何（非 3D 投影），需要根据参数手动计算虚线位置。

- 瓶盖内腔：虚线矩形（内径 × 内腔深）
- 瓶身内腔：虚线矩形（内径 × 内深）
- 刷杆空心杆：虚线线条
- 内塞中心孔：虚线圆（俯视图已有，正视图需添加）

**预估**：每个组件增加 10-20 行。

### 3.4 标题栏规范化（难度：中，收益：中）

重新设计标题栏为网格布局，包含：

```
┌──────┬──────┬────────┬──────────────┐
│ 设计 │      │  图名  │ 唇釉瓶-瓶盖  │
├──────┼──────┤        ├──────────────┤
│ 审核 │      │  图号  │ LG-CAP-001   │
├──────┼──────┼────────┼──────────────┤
│ 比例 │ 2:1  │ 材料   │ PP           │
├──────┼──────┼────────┼──────────────┤
│ 单位 │ mm   │ 日期   │ 2026-03-11   │
├──────┴──────┴────────┼──────────────┤
│ [投影符号]           │ 版本 A       │
└──────────────────────┴──────────────┘
```

**预估**：共享标题栏函数 ~80 行。

### 3.5 真实 3D 投影轮廓（难度：高，收益：极高）

从 CadQuery 3D 模型生成正交投影线框，替代手绘矩形。

**技术路线**：

```python
# 方案 A：CadQuery 内置 SVG 导出
import cadquery as cq
cq.exporters.export(solid, "front.svg", opt={"projectionDir": (0, -1, 0)})
```

**优势**：
- 真实轮廓（含锥度、圆角、曲线外壁、螺纹等）
- 自动区分可见/不可见边
- 无需手动计算几何

**挑战**：
- CadQuery SVG 导出生成的是纯轮廓线，无尺寸标注
- 需要将投影 SVG 与标注系统集成
- 投影方向、缩放、位置需要精确控制
- 剖视图需要先对实体做布尔切割再投影

**预估**：核心投影引擎 ~200 行 + 与标注系统集成 ~150 行。

### 3.6 DXF/PDF 导出（难度：中，收益：中）

| 格式 | 库 | 说明 |
|------|-----|------|
| DXF | `ezdxf`（pip 可装） | 兼容 AutoCAD，支持图层、标注、填充 |
| PDF | `cairosvg` 或 `weasyprint` | SVG → PDF 转换 |

## 四、分阶段实施方案

### 第一阶段：SVG 原语升级（1-2 天）

**目标**：不改布局，仅修正绘图原语使其符合国标基本要求。

| 步骤 | 内容 | 优先级 |
|------|------|--------|
| 1 | 新建 `src/products/lip_gloss/drawings/primitives.py` — 共享绘图基础库 | P0 |
| 2 | 实现标准图元：实心箭头、尺寸界线、点划线中心线、剖面线 pattern、剖切符号 | P0 |
| 3 | 四个 `*_sheet.py` 改用共享库，消除重复代码 | P0 |
| 4 | 修正中心线 dash 模式 | P0 |

**交付物**：四张图纸的箭头、中心线、剖面线符合国标视觉标准。

### 第二阶段：剖视图与虚线（1-2 天）

**目标**：剖视图具有专业外观，正视图显示不可见轮廓。

| 步骤 | 内容 | 优先级 |
|------|------|--------|
| 1 | 剖视图实体区域填充 45° 剖面线 | P0 |
| 2 | 正视图添加剖切符号（A-A 标注 + 投影箭头） | P0 |
| 3 | 正视图添加不可见轮廓虚线（内腔、螺纹） | P1 |
| 4 | 清理尺寸文字 — 去掉中文描述，改为纯数值+符号 | P1 |

**交付物**：剖视图可清晰区分实体截面与空腔，正视图显示内部结构。

### 第三阶段：布局与标题栏（1-2 天）

**目标**：图纸整体布局符合第一角投影法，标题栏规范化。

| 步骤 | 内容 | 优先级 |
|------|------|--------|
| 1 | 视图重排为第一角投影布局（主视图上方，俯视图下方） | P1 |
| 2 | 视图之间保持投影对齐（宽度/高度对应） | P1 |
| 3 | 标题栏改为网格式，增加图号、材料、签名栏、投影符号 | P1 |

**交付物**：图纸布局和标题栏达到专业工程图水平。

### 第四阶段：真实 3D 投影（3-5 天）✅ 已完成

**目标**：从 CadQuery 3D 模型自动生成真实投影轮廓，替代手绘矩形。

| 步骤 | 内容 | 优先级 | 状态 |
|------|------|--------|------|
| 1 | 实现 3D→2D 正交投影引擎（利用 CadQuery/OCP 投影 API） | P2 | ✅ 已完成 |
| 2 | 实现剖切面投影（布尔切割 + 投影） | P2 | ✅ 已完成 |
| 3 | 投影 SVG 与标注系统集成 | P2 | ✅ 已完成 |
| 4 | 支持 spline 外壁、螺纹、圆角等复杂特征的真实投影 | P2 | ✅ 已完成 |

**交付物**：正视图/剖视图/俯视图反映真实零件外形，含圆角、锥度、曲线轮廓。

#### 第四阶段实施记录

**新增文件**：
- `src/products/lip_gloss/drawings/projection.py` — 3D→2D 正交投影引擎（~280 行）

**技术实现**：
- **HLR 投影**：利用 OCCT `HLRBRep_Algo` 隐线消除算法，自动区分可见轮廓（粗实线）和隐藏边（虚线）
- **剖切投影**：通过 `BRepAlgoAPI_Cut` 布尔切割生成半剖体，再做 HLR 投影；通过 `BRepAlgoAPI_Section` 提取截面线用于剖面线填充
- **曲线离散化**：`GCPnts_TangentialDeflection` 自适应采样，精确还原 spline 曲线、圆角等复杂几何
- **SVG 路径**：将 OCCT Edge 转换为 SVG `<path d="M...L...">` 元素，支持缩放和定位

**修改文件**（向后兼容）：
- `cap_sheet.py` / `bottle_sheet.py` / `wand_sheet.py` / `wiper_sheet.py` — 新增 `solid` 可选参数
  - `solid` 非 None → 调用投影引擎生成真实 3D 投影
  - `solid` 为 None → 保持原有参数化手绘逻辑（向后兼容）
- `cap.py` / `bottle.py` / `wand.py` / `wiper.py` — `generate()` 中将 `solid` 传递给工程图导出

**公共 API**：
```python
# 正视图投影
project_to_svg(solid, DIR_FRONT, scale=2.0, cx=100, cy=80) -> list[str]

# 剖切投影（半剖 + 截面线）
section_to_svg(solid, DIR_FRONT, cut_origin=(0,0,0), cut_normal=(0,1,0), ...) -> list[str]

# 俯视图投影
project_top_to_svg(solid, scale=2.0, cx=100, cy=80) -> list[str]

# 投影包围盒
project_bbox(solid, DIR_FRONT) -> (xmin, ymin, xmax, ymax)
```

## 六、风险与注意事项

1. **SVG 字体兼容性**：中文字体在不同平台渲染不一致，建议指定 fallback 链 `font-family="SimHei, Microsoft YaHei, Arial, sans-serif"`
2. **剖面线性能**：大面积 45° 平行线在 SVG 中可能导致渲染卡顿，建议使用 `<pattern>` 定义而非逐条 `<line>`
3. **3D 投影精度**：CadQuery SVG 导出的线框可能包含大量微小线段，需要做简化处理
4. **向后兼容**：重构应保持 API 接口不变（`export_*_sheet(params, svg_path)` 签名不变），确保前端无需改动
5. **测试策略**：建议为共享绘图库编写单元测试，验证箭头尺寸、线型参数、标题栏字段等
