# AiCad 3D 交互拉升功能可行性报告

> 日期：2026-03-12
> 版本：v1.0
> 范围：唇釉瓶四组件（Cap / Bottle / Wand / Wiper）3D 交互参数编辑

---

## 一、需求概述

### 1.1 需求描述

在网页 3D 渲染界面中，用户可通过拖拽/拉升模型上的交互句柄来直接修改几何参数（如高度、外径等），取代当前"在参数面板输入数值 → 点击生成"的操作路径，缩短参数探索的交互链路。

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| 直观性 | 拖拽即可改参数，无需切换到参数面板 |
| 零延迟 | 拖拽过程中即时视觉反馈，无需等待后端重建 |
| 低侵入 | 不改变现有生成流程，仅在查看器层新增交互能力 |

---

## 二、现有架构分析

### 2.1 技术栈概要

| 层级 | 技术 | 关键文件 |
|------|------|---------|
| 3D 渲染 | Three.js v0.160.0 + STL 格式 | `web/src/components/viewer/ViewerModal.vue` |
| 已有交互 | OrbitControls / TransformControls / Raycaster | 同上 |
| 2D 拖拽编辑 | SVG 贝塞尔曲线拖拽 | `web/src/components/param/ProfileEditor.vue` |
| 参数系统 | 核心参数 + 派生参数 + 跨组件约束 | `src/core/param_system.py` |
| 后端建模 | CadQuery / OpenCascade | `src/core/modeler.py` |
| 生成 API | POST `/api/generate` → STL/STEP/SVG | `scripts/web_server.py` |

### 2.2 已有交互能力清单

当前 `ViewerModal.vue` 已实现以下交互功能：

| 功能 | 实现方式 | 可复用性 |
|------|---------|---------|
| 轨道旋转 / 缩放 / 平移 | `OrbitControls` | 高 — 拖拽句柄时需暂停 |
| 组件点击选择 | `Raycaster` + `intersectObjects` | 高 — 句柄检测可复用相同逻辑 |
| 选中高亮 | `emissive` 颜色变更 | 高 — 句柄选中时可同样高亮 |
| 平移 / 旋转 / 缩放变换 | `TransformControls` + W/E/R 快捷键 | 参考 — 拖拽交互模式类似 |
| 截面切割 | `THREE.Plane` + 滑块 | 低 — 独立功能 |
| 装配 / 爆炸视图 | 后端装配位置 + 前端偏移 | 中 — 句柄需跟随装配位移 |

### 2.3 数据流现状

```
参数面板 (ParamField)
  → paramsStore.setParam()
  → 派生参数自动计算 (updateDerivedParams)
  → 用户点击"生成"
  → POST /api/generate (参数 JSON)
  → CadQuery 建模 (2-5 秒)
  → 导出 STL 文件
  → 前端 STLLoader 加载
  → Three.js 渲染
```

### 2.4 核心约束

**后端重建耗时 2-5 秒**，无法实现拖拽过程中的实时模型重建。这一约束是所有方案设计的出发点。

## 三、技术方案对比

### 3.1 方案 A：STEP + opencascade.js（前端 BRep 拓扑解析）

**原理**：引入 opencascade.js（OpenCascade 的 WebAssembly 编译版本），在前端直接解析 STEP 文件的 BRep 拓扑结构。用户点击模型表面时，通过拓扑信息精确识别语义面（如"瓶盖顶面""瓶身侧面"），然后将拖拽方向映射到对应参数。

**技术路径**：
1. 后端已在生成时输出 STEP 文件（`step_url` 字段已存在）
2. 前端引入 opencascade.js WASM 模块，解析 STEP 获取 `TopoDS_Shape`
3. 通过 `TopExp_Explorer` 遍历 Face，结合法线方向和空间位置标注语义
4. 后端在 build 过程中为关键面添加元数据映射（面 → 参数）
5. 用户点击面 → 匹配语义 → 拖拽方向投影 → 修改参数

**评估**：

| 维度 | 评价 |
|------|------|
| 面识别精度 | 最高 — BRep 拓扑完整保留面/边/顶点关系 |
| 实现复杂度 | 极高 — 需深入掌握 OCCT 拓扑 API |
| 新增依赖 | opencascade.js WASM ~30-50MB |
| 首次加载影响 | 严重 — WASM 模块下载 + 编译耗时长 |
| 调试难度 | 高 — WASM 中的 OCCT 几乎无调试工具 |
| 面标注维护成本 | 高 — 每个组件的每次建模流程变更都需同步标注 |
| 预计工期 | 8-12 周 |
| 技术风险 | 高 |

**结论**：技术上可行但代价过高，不推荐。

---

### 3.2 方案 B：STL 区域划分 + 法线分析

**原理**：在 STL 三角网格模型上，利用面法线方向和空间坐标将表面划分为语义区域（顶部、侧面、底部等）。后端预定义每个区域对应的参数和拖拽轴向，前端通过 Raycaster 获取击中三角面片的法线来判断用户点击的区域。

**技术路径**：
1. 后端新增 API 返回"区域定义"（法线范围 → 参数映射 → 拖拽方向）
2. 前端 Raycaster 获取 `intersects[0].face.normal`（法线）和 `intersects[0].point`（击中坐标）
3. 匹配法线方向到预定义区域
4. 拖拽时对 mesh 施加简单缩放变形做预览

**评估**：

| 维度 | 评价 |
|------|------|
| 面识别精度 | 中等 — 圆角/倒角区域法线混合，判断模糊 |
| 实现复杂度 | 中等 |
| 新增依赖 | 无 |
| 区域边界问题 | STL 三角面片在曲面上分布不均，边缘法线不可靠 |
| 内腔面可达性 | 差 — 外表面遮挡了内腔面，无法直接拖拽 |
| 预计工期 | 3-5 周 |
| 技术风险 | 中 |

**结论**：可行但法线分析精度不够，用户体验存在模糊交互的风险。

---

### 3.3 方案 C：3D 参数句柄（Gizmo）— 推荐方案

**原理**：在模型关键位置放置可拖拽的 3D 句柄（箭头/锥体），每个句柄明确绑定一个参数和一个拖拽方向。用户拖拽句柄时，前端对 mesh 施加即时几何变形（缩放/平移）做视觉预览，参数暂存于查看器内部；关闭查看器时批量回写参数到系统，用户下次点击"生成"时用新参数重建精确模型。

**技术路径**：
1. 后端根据组件类型和当前参数计算句柄位置、方向、值域范围
2. 前端用 `THREE.ArrowHelper` 或自定义 Mesh 在对应位置渲染箭头句柄
3. 句柄作为组件 mesh 的子对象，自动跟随装配位移和旋转
4. Raycaster 检测句柄（优先级高于模型本体）→ 进入拖拽模式
5. 拖拽时即时缩放 mesh + 更新数值标签 → 参数暂存到 viewerStore
6. 关闭查看器时将暂存参数写入 paramsStore

**评估**：

| 维度 | 评价 |
|------|------|
| 用户体验 | 好 — 每个句柄语义明确，零歧义 |
| 实现复杂度 | 中低 — 完全基于 Three.js 原生能力 |
| 新增依赖 | 无 |
| 可控性 | 最高 — 句柄是独立对象，完全控制外观和行为 |
| 渐进实施 | 友好 — 可先实现 2 个句柄验证，再扩展 |
| 预计工期 | 2-4 周 |
| 技术风险 | 低 |

**结论**：推荐方案。实现代价最低、风险最小、用户体验明确。

---

### 3.4 方案 D：实时预览优化（辅助方案）

作为方案 C 的辅助策略，用于解决拖拽过程中的视觉反馈问题。

| 子方案 | 原理 | 效果 | 成本 |
|--------|------|------|------|
| D1. 即时几何变形 | 拖拽时对 mesh 施加 scale/position 变换 | 方向性反馈足够，细节失真 | 极低（~20 行代码） |
| D2. STL 预缓存 | 预生成参数梯度的 STL 系列 | 流畅但存储大 | 中（后端批量生成） |
| D3. WebSocket 流式重建 | 拖拽时流式发送参数请求 | 接近实时 | 高（架构大改） |

**推荐**：D1 作为必选辅助方案，D2/D3 为远期可选增强。

---

### 3.5 方案对比总结

| 方案 | 工期 | 技术风险 | 新依赖体积 | 用户体验 | 推荐度 |
|------|------|---------|-----------|---------|--------|
| A. STEP + opencascade.js | 8-12 周 | 高 | ~40MB WASM | 最像专业 CAD | 不推荐 |
| B. STL 区域划分 | 3-5 周 | 中 | 无 | 中等（边界模糊） | 备选 |
| **C. 3D 参数句柄** | **2-4 周** | **低** | **无** | **好（语义明确）** | **推荐** |
| D. 预览优化 | 辅助 | — | — | 增强 | D1 必选 |

## 四、推荐方案详细设计

### 4.1 核心交互流程 — 延迟应用模型

本方案的关键创新在于**延迟应用**策略：拖拽过程中不触发后端重建，彻底消除交互延迟。

```
┌──────────────────────────────────────────────────────────┐
│  打开 3D 查看器（显示已生成的 STL 模型）                  │
│    ↓                                                      │
│  选中组件 → 显示该组件的参数句柄（箭头 Gizmo）            │
│    ↓                                                      │
│  拖拽句柄                                                 │
│    ├── 即时 mesh 缩放 / 平移变形（零延迟视觉反馈）        │
│    ├── 实时更新数值标签（"高度: 25.0 → 27.3mm"）          │
│    └── 参数暂存于 viewerStore（不写 paramsStore）          │
│    ↓                                                      │
│  可继续拖拽其他句柄（多参数连续调整）                      │
│    ↓                                                      │
│  关闭查看器                                               │
│    ├── 批量将暂存参数写入 paramsStore                      │
│    ├── 参数面板自动显示更新后的值                          │
│    └── 提示"参数已修改，请重新生成"                        │
│    ↓                                                      │
│  用户点击"生成" → 后端用新参数重建精确模型（2-5 秒）       │
└──────────────────────────────────────────────────────────┘
```

**该模型的核心优势**：

| 特性 | 说明 |
|------|------|
| 拖拽零延迟 | 所有视觉反馈均为纯 Three.js 前端计算，不涉及网络请求 |
| 多参数合并 | 一次编辑会话中可连续调整多个参数，最终只需一次重建 |
| 重建延迟无感 | 2-5 秒重建被推迟到用户主动点击"生成"时，用户已有心理预期 |
| 与现有流程一致 | 参数修改 → 生成 的流程不变，仅新增了一种参数输入方式 |

### 4.2 句柄配置定义

每个组件定义 2 个最关键的核心参数句柄：

| 组件 | 句柄 | 绑定参数 | 句柄位置 | 拖拽方向 | 预览变形方式 |
|------|------|---------|---------|---------|------------|
| Cap（瓶盖） | 高度箭头 ↑ | `height_mm` | 顶面中心 | Z 轴正方向 | `mesh.scale.z` |
| Cap（瓶盖） | 外径箭头 → | `outer_od_mm` | 侧面中点 | 径向（X 轴） | `mesh.scale.x/y` |
| Bottle（瓶身） | 高度箭头 ↑ | `total_height_mm` | 顶面中心 | Z 轴正方向 | `mesh.scale.z` |
| Bottle（瓶身） | 外径箭头 → | `body_od_mm` | 侧面中点 | 径向（X 轴） | `mesh.scale.x/y` |
| Wand（刷杆） | 总高箭头 ↓ | `total_height_mm` | 底端 | Z 轴负方向 | `mesh.scale.z` |
| Wand（刷杆） | 外径箭头 → | `outer_od_mm` | 盖部中点 | 径向（X 轴） | `mesh.scale.x/y` |
| Wiper（内塞） | 高度箭头 ↑ | `height_mm` | 顶面中心 | Z 轴正方向 | `mesh.scale.z` |
| Wiper（内塞） | 外径箭头 → | `outer_od_mm` | 侧面中点 | 径向（X 轴） | `mesh.scale.x/y` |

**句柄数据结构**：

```
DragHandle:
  id          : 字符串   — 唯一标识（如 "cap_height"）
  paramKey    : 字符串   — 绑定的参数键（如 "height_mm"）
  position    : 三维坐标 — 句柄初始位置（CadQuery Z-up 坐标系）
  axis        : 三维向量 — 拖拽方向（单位向量）
  color       : 16 进制  — 句柄颜色
  label       : 字符串   — 显示标签（如 "高度: 25.0mm"）
  min / max   : 数值     — 参数允许范围
  currentValue: 数值     — 当前参数值
```

### 4.3 即时预览变形策略

拖拽时对 mesh 施加简单几何变换模拟参数变化，提供即时视觉反馈：

| 参数类型 | 变形方式 | 示例 |
|---------|---------|------|
| 高度参数 | `mesh.scale.z` 按比例缩放 | 高度从 25→30mm，scale.z 变为 1.2 |
| 外径参数 | `mesh.scale.x` 和 `mesh.scale.y` 同步缩放 | 外径从 20→24mm，scale.x/y 变为 1.2 |

**缩放公式**：

```
scaleFactor = newValue / originalValue
```

**预览精度说明**：简单缩放无法准确反映圆角、内腔、螺纹等细节的变化，但作为方向性参考已足够。精确结果在用户点击"生成"后由 CadQuery 重建呈现。

### 4.4 坐标系对齐

CadQuery 使用 Z-up 坐标系，Three.js 使用 Y-up 坐标系。当前代码通过 `mesh.rotation.x = -Math.PI / 2` 进行转换。

句柄处理方式：
- 后端以 CadQuery 坐标系（Z-up）定义句柄 position 和 axis
- 前端将句柄作为 mesh 的子对象添加（`mesh.add(handleMesh)`）
- 句柄自动继承 mesh 的旋转变换，无需额外坐标转换

## 六、技术风险评估

### 6.1 已识别风险

| 风险 | 严重性 | 发生概率 | 缓解措施 |
|------|--------|---------|---------|
| mesh 缩放预览细节失真 | 低 | 确定发生 | 可接受 — 仅作方向性参考，精确结果由重建提供 |
| CadQuery Z-up vs Three.js Y-up 坐标转换 | 低 | 低 | 句柄作为 mesh 子对象，自动继承旋转变换 |
| 句柄被模型遮挡不可点击 | 中 | 中 | 句柄设置 `depthTest: false` + 半透明渲染，始终可见 |
| 多组件装配模式下句柄重叠 | 低 | 中 | 仅显示当前选中组件的句柄 |
| 用户忘记在关闭查看器后重新生成 | 低 | 中 | 关闭时弹出提示"参数已修改，建议重新生成" |
| 派生参数联动导致参数冲突 | 低 | 低 | 拖拽值夹紧到 `[min, max]` 范围，派生参数在回写时自动重算 |

## 七、与现有 ProfileEditor 的对比和复用

当前系统已有 `ProfileEditor.vue` 实现了 2D SVG 拖拽编辑轮廓曲线的能力，与 3D 句柄系统存在对比关系：

| 维度 | ProfileEditor（2D SVG 拖拽） | 3D 参数句柄 |
|------|----------------------------|-------------|
| 编辑对象 | 贝塞尔曲线控制点 | 标量参数（高度、外径等） |
| 渲染技术 | SVG `<circle>` + `<path>` | Three.js ArrowHelper / 自定义 Mesh |
| 坐标转换 | `toSvgX/Y` ↔ `fromSvgX/Y`（像素↔毫米） | 屏幕像素 → Three.js 射线 → 拖拽轴投影 |
| 约束系统 | `clampPoint`（区域感知夹紧） | ParamDef 的 `min/max` + DerivedRule 范围 |
| 拖拽事件 | `pointerdown/move/up` 在 SVG 元素上 | `pointerdown/move/up` 在 Canvas 上 |
| 数据流 | `writePoints → setParam → scheduleAutoGenerate` | `onDrag → 暂存 → 关闭时 setParam` |
| 反馈延迟 | 650ms 防抖后重建 | 即时缩放预览 + 关闭后回写 |

**可复用的设计模式**：

1. **拖拽状态管理**：`dragging` ref + pointer capture 的模式可直接迁移
2. **约束夹紧**：ParamDef 的 min/max 范围检查逻辑复用
3. **防抖重建**：`scheduleAutoGenerate` 防抖机制已成熟（用于关闭后的重建）
4. **坐标映射思路**：2D 的像素↔毫米映射可推广为 3D 的射线投影↔参数增量

**互补关系**：ProfileEditor 处理 2D 轮廓曲线的精细编辑，3D 句柄处理标量参数的快速调整。两者共用相同的参数系统和重建管道，用户可根据需求选择合适的编辑方式。

## 九、结论

### 9.1 技术可行性

**高。** 方案 C（3D 参数句柄）+ D1（即时缩放预览）完全基于现有 Three.js 能力和已验证的参数数据流，无需引入大型外部依赖，技术风险低。

### 9.2 延迟应用策略的可行性

**高。** 通过将参数回写推迟到关闭查看器时执行，彻底消除了拖拽过程中 2-5 秒的后端重建延迟。用户在 3D 查看器中获得即时的视觉反馈（mesh 缩放变形），而精确重建被延迟到用户主动"生成"时——此时用户已有等待重建的心理预期，延迟感为零。

### 9.3 建议

1. **推荐实施方案 C + D1**，从 Cap 组件开始验证
2. 第一阶段完成后评估用户体验，再决定是否推进第二、三阶段
3. 远期可考虑 D2（STL 预缓存）进一步提升预览精度
